# 规则细则：避坑硬规则与失真红线

> 本文档是 SKILL.md 中规则层的展开版，说明每条规则的来源逻辑与执行判定，供 agent 在自检时查阅细节。

---

## 一、避坑硬规则（7 条，违反即停止）

### 规则 1：凹面脸不靠加高鼻梁救立体度

- **逻辑**：凹面脸的凹陷感来自鼻基底/面中支撑不足，单独加高鼻梁会拉高面中轴线，与凹陷的基底形成更大落差，**越加越显凹陷**。
- **修图判定**：方案中出现"增高鼻梁 / 垫高山根"且脸型判定为凹面凸嘴脸 → 删除该操作，替换为"鼻翼旁区域提亮 + 面中光影上提"。
- **实测验证**：案例 #003（2 组凹面凸嘴照片），光影版与大改版均未触发加鼻梁。

### 规则 2：方圆脸不修细窄鼻梁、不切式收窄下颌角

- **逻辑**：方圆阔面脸的协调感依赖骨量与量感匹配，细窄鼻梁会头重脚轻，切式收下颌角破坏原生骨相抗老优势。
- **修图判定**：方案中出现"细化鼻梁 / 大幅收窄下颌角"且脸型为方圆阔面脸 → 替换为"鼻影加宽匹配量感 + 外轮廓压暗收窄（保留骨量）"。
- **实测验证**：案例 #002，T 区仅用光影不液化鼻形，下颌角只压暗不切。

### 规则 3：方圆脸下巴用圆润 U 型，不修尖下巴

- **逻辑**：尖下巴与宽下颌脱节，导致头重脚轻、轮廓断裂。
- **修图判定**：方案中出现"修尖下巴"且脸型为方圆阔面脸 → 替换为"保持圆润 U 型，仅做光影过渡"。
- **实测验证**：案例 #002，复盘确认"下巴没尖"。

### 规则 4：月亮脸 / 窄长脸下巴不过度前兜或后缩

- **逻辑**：月亮脸本身过兜，再前兜加重畸形感；硬缩则破坏侧面平衡。
- **修图判定**：下巴操作幅度超过"微调"级别 → 停止，提示用户该项属于骨相大改。

### 规则 5：菱形脸不填平太阳穴

- **逻辑**：填平太阳穴会横向拓宽脸部面积；生理浅凹是正常结构。
- **修图判定**：方案中出现"填充 / 提亮太阳穴使其饱满"且颧突明显 → 替换为"颧骨高光内移 + 眉尾外延"。
- **实测验证**：案例 #002 / #003，"太阳穴保留生理浅凹不填平"均正确执行。

### 规则 6：窄长脸不盲目瘦脸

- **逻辑**：窄长脸再瘦会拉长中庭、加重苦相；纵向拉颅顶同理拉长比例。
- **修图判定**：方案中出现"整体瘦脸 / 纵向增高颅顶"且脸型为窄长脸 → 替换为"卧蚕加宽 + 上唇微丰缩短中庭；颅顶只横向补饱满"。
- **实测验证**：案例 #001 / #003，"头型只横向不纵向"多次正确触发。

### 规则 7：高光永远向中轴线内聚，不横向提亮脸外侧

- **逻辑**：横向提亮外侧会拓宽脸型，与"折叠度内聚"的核心目标背道而驰。
- **修图判定**：任何提亮操作前检查位置——外侧区域一律改为压暗，高光点向内移动。

## 二、失真红线（4 条，优先级高于一切美化需求）

| # | 红线 | 执行细则 |
|---|------|----------|
| 1 | **默认仅光影与轻度液化** | 骨相形态大改（改下颌角、改嘴凸形态、垫高鼻梁）必须用户明确说"我要大改"才解锁，且执行前输出"此为模拟效果，非本人真实外观"警示 |
| 2 | **大改不解锁避坑规则** | "我要大改"只放宽幅度，不豁免第四节硬规则——大改范围内仍逐条自检 |
| 3 | **辨识度保持** | 眼睛形状、鼻子基础形态、脸型骨架默认不动；非面部元素（发型 / 服饰 / 背景 / 宠物 / 配饰）一律保留 |
| 4 | **非医美建议** | 修图定位是审美参考；用户询问医疗美容时只做科普性提示并建议咨询正规医疗机构，每次大改后重复声明 |

## 三、复盘卡评级规则

- 四维：三庭比例 / 面部折叠度（高光内聚）/ T 区立体感 / 下颌线清晰度
- 评级档位：**改善 / 持平 / 过度 / N/A**
- **N/A 判定**：凡与本脸型方案无关、本次未处理或本就不适用的维度 → 标 N/A，说明写"本方案不涉及，非未完成"；禁止把不适用维度标成"持平"误导用户
- 有"过度"项时主动提示可回退

---

## 四、迭代协议（防五官漂移的核心机制）

1. 单次只改 1-2 个区域 → 发对比图 → 用户确认 → 下一步
2. 失败即回退（"回退"指令），不做破坏性叠加修改
3. 修图指令必须具体到区域和方向，禁止"变美一点""P 好看点"这类模糊指令
4. 多照片同人重判：新照片一律重新走诊断流程，判定不一致时列出分歧点
